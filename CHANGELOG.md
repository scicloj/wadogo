# Change Log

## [1.1.0-alpha2-SNAPSHOT]

### Added

* new kinds: `:identity`, `:radial`, `:point`, `:sequential` and `:diverging` (both with `:transform` `:linear`, `:log`, `:pow` or `:symlog` and an `:interpolator` function), as d3 `scaleIdentity`, `scaleRadial`, `scalePoint`, `scaleSequential*`, `scaleDiverging*`
* `:clamp`, `:unknown` and `:round` attributes for continuous ranges (d3 `clamp`, `unknown`, `rangeRound`); `:unknown` also for discrete kinds (values outside the domain of `:bands`, `:point`, `:ordinal`; `nil`/`NaN` for `:quantize`, `:quantile`, `:threshold`, `:histogram`)
* `:bands` - `:align-outer` (d3 `align`, distribution of the outer padding) and `:round` (d3 `round`); `:point` uses the same `:align-outer`
* `:clamp` of `:interpolated` uses the smallest and largest domain value
* `kind-info` - description of a scale kind; namespace docstrings for every kind, docstrings for all public functions
* scales can be used with `apply` (one or two arguments)
* oracle tests: scale mappings against d3-scale 4.0.2 (`utils/d3/d3_scales.mjs`), quantile strategies against R `quantile(type = 1..9)` (`utils/quantile/quantile_oracle.R`)
* `nice` - extends the domain of continuous scales to the nearest outer ticks (d3 style: repeated until the tick grid is stable)
* `nice` with options `{:max-extension f :max-count n}` - limits the extension to fraction `f` of the range span, trying tick counts upward from the scale's own; the scale is unchanged when none qualifies
* `:ticks-method :pretty` - ticks as R's `pretty()` (inside the domain only); log scales choose the grid with number of ticks closest to requested (subdivisions of powers: all multipliers as d3, 1-2-5 and 1-5 for base 10; or powers), datetime scales R's `pretty()` for date-times; `:ticks-params {:min-n ...}`
* `:test` alias (cognitect test-runner), oracle data in `test/resources` generated by scripts in `utils/` (R and d3)

### Changed

* [breaking] `:symlog` - the constant `:C` defaults to `1.0` (as d3, was `1/ln(base)`); `:base` is deprecated and ignored (it cancels in the mapping, and no longer completes a one-value domain)
* [breaking] `:log` - a domain containing or crossing zero throws `ex-info` (was `NaN` results)
* [breaking] `:quantile` - default `:estimation-strategy` is `:r7` (as d3 and R, was `:legacy`); values outside the sample are mapped to the first or last interval (as d3, was `nil`)
* [breaking] `:ordinal` - a range shorter than the domain is cycled (as d3, was `nil` for the extra values); values outside the domain give `:unknown` also when a second argument is given (was the second argument); `:sort? true` on values which can't be compared throws `ex-info` (was `ClassCastException`); `inverse` returns the first domain value mapped to a range value (was the last)
* [breaking] `:datetime` - `Instant`, `ZonedDateTime` and `OffsetDateTime` are converted to the UTC `LocalDateTime` (ticks, `nice` and `format` failed); a two-value domain keeps its order (was sorted), so reversed domains map as d3
* [breaking] `nil` and `NaN` given to continuous kinds return `:unknown` (`nil` by default; was `NaN` or an exception)
* [breaking] internal functions of `wadogo.common` and `wadogo.utils` are marked `:no-doc` (`ticks-method`, `linear-ticks`, `discrete->ticks` and `wadogo.ticks.linear/step-mult` are private, `wadogo.utils/ensure-seq-content` and `append-infs` moved into their kinds); `wadogo.scale` is the public API
* degenerate domains (equal ends) of `:log`, `:pow` and `:symlog` behave as `:linear` (values below map to the range start, above to the range end, equal to the middle; was `NaN`)
* `:quantize` - a two-value domain in descending order throws `ex-info` (was a fastmath exception)
* `:threshold` - the domain must be in ascending order (`ex-info`), repeated thresholds are allowed, a range shorter than the intervals gives `nil` (was an exception)
* `:quantize` - inner thresholds computed as in d3 (exact match on borders)
* `:identity` returns doubles
* `size` of a continuous range with non-numerical ends (`:sequential`, `:diverging` with e.g. a color interpolator) is `nil`
* `:bands` - `inverse` returns `:unknown` for padding and values outside the range
* default datetime ticks of a reversed domain are the reversed ticks (was empty)
* [breaking] default log ticks: number of ticks is capped by the number of powers of the base (no fractional powers like `3.162...`), negative domains return all powers, domains with fewer than two powers inside get linear ticks
* default linear ticks follow d3-array 3.2 rounding, a domain end equal to a tick (up to floating point error) is not dropped anymore, zero tick is `0.0` (was `-0.0` for some domains)
* datetime ticks for a non-positive number of ticks are empty (was: division by zero)
* build: `deps.edn` only (`project.clj` removed), `clojure -T:build jar | install | deploy`, tests `clojure -M:test`

### Fixed

* `:bands` - `inverse` always threw `NullPointerException`
* `:bands` - repeated domain values are removed (as d3; a repeated value got an extra band and mapped to the last one)
* `:datetime` - a degenerate domain (equal ends) threw `ArithmeticException`, now behaves as `:linear` (also a degenerate range in the inverse)
* `:interpolated` - the inverse solves `forward(x) = y` by bisection (was: the same method on swapped points, exact only for `:linear`), so it's exact for any monotone method; repeated range values (plateaus) no longer prevent creating the scale; values beyond the domain ends are searched outside the domain while the extrapolated curve keeps moving toward them, `NaN` otherwise (with `:clamp`: the nearer domain end); extra values of the longer of `:domain` and `:range` are dropped from the stored domain and range; notebook examples use monotone methods (`:pchip`, `:monotone`, step methods) instead of `:shepard` and `:loess`
* `:interpolated` - `inverse` with an interpolator function used the forward pairs
* `:quantile` - samples giving repeated quantiles threw (fastmath `step-before` requires strictly increasing steps)
* datetime formatter threw for fewer than two ticks; the pattern follows the domain span then
* range formatter (`:threshold` with `:range :intervals`) never received `:formatter-params`; default `:endpoints :open` (`< 0.0`, `[0.0, 1.0)`, `≥ 1.0`)
* `size` of a datetime domain was negative
* `(s/scale :quantile)` and `(s/scale :histogram)` failed while the docstring promised defaults for all kinds (docstring corrected: they need a domain)
* notebook: `:loess` example uses fastmath 3 options map, Clerk 0.18.1158 (`:dev` alias)
* `:histogram` default estimation (`:default` was rejected by fastmath 3), `:freedman-diaconis` is the default, `:default` is its alias
* `:datetime` scale ignored `:formatter`
